# xfcemlg — resolution record

A running record of recurring issues and their current resolution, in the
style of the preceding devuan-kde-setup. The primary documentation lives in
README.md (`docs/BUILDING.md` for the live-ISO path). Verified against v0.6.0.

| Area | Current resolution | Main implementation |
|---|---|---|
| Palette-magenta Devuan logo | fastfetch's built-in `Devuan` logo carries no `$N` colour placeholders, so it can only be rendered in the palette magenta and clashed with Darkmatter. The art is therefore deployed to `~/.config/fastfetch/devuan.txt` instead, each literal `$` escaped as `$$`. It is single-coloured on purpose: the logo is a solid mass of `$` glyphs, and a colour token after a run of `$$` pairs is parsed as a literal digit, so a two-tone version silently corrupts the art. | `scripts/19-fastfetch.sh`, `configs/fastfetch/devuan.txt` |
| `ports()` aborted the rest of the shell config | The vendored payload defines `alias ports='netstat -tulanp'`, and the override that redefines `ports` as an `ss` function was written with the `unalias` *inside* the `if` block. Bash parses a whole compound command before running any of it, and the file is sourced by an interactive shell where aliases expand as it reads — so the parser reached `ports() {` and expanded the live alias to `netstat -tulanp() {`, a syntax error that killed the remainder of the file, every new terminal. The `unalias` is now its own statement, so the alias is gone before the definition is read. | `configs/bash/99-xfcemlg-overrides.sh` |
| Prompt that could not win | Both `configs/bash/prompt.sh` and the vendored `prompt.bash` build a `PROMPT_COMMAND` chain. The payload *prepends* its builder and ours appends, so loading both left ours running last and the vendored prompt was never seen — the payload looked broken when it was merely out-prioritised. `rc.sh` now skips the xfcemlg prompt when the payload is present. | `configs/bash/rc.sh` |
| Phantom package names | `xfce4-pager` (workspace pager is built into `xfce4-panel`), `mate-disk-usage-analyzer` (dropped upstream) and `xcursor-breeze` (renamed upstream) do not exist in Debian trixie / Devuan Excalibur. Fixed to `baobab` / `breeze-cursor-theme` and removed the pager; the apt-checks tier verifies every referenced package against the real archive so this class of bug fails `make check`. | `scripts/21-theme.sh`, `scripts/33-useful-apps.sh`, `scripts/verifySetup.sh`, `tests/apt-checks.sh` |
| `slim absent` FAIL that no re-run could clear | `10-xfce-core.sh` walked its display-manager rivals as `dm_enabled_runlevel "$dm" \|\| continue`, so a rival that was merely *installed* was skipped whole — and the purge offer lived inside that skipped block. `slim` (pulled in by `task-xfce-desktop`, then in no OpenRC runlevel) was therefore unpurgeable by the toolkit, `verifySetup.sh` failed it on every single run, and "re-run 10-xfce-core.sh" could never fix it. Enabling is now a separate branch from purging: any installed rival is offered for purge whether or not it was ever enabled, and the new `dm_sysvinit_links` reports the stale `/etc/rc[0-6].d/S*` links a distro DM install leaves behind (dormant while `/etc/init.d/rc` is OpenRC's wrapper, a console fight the day anyone boots plain sysvinit). | `scripts/10-xfce-core.sh`, `scripts/verifySetup.sh` |
| `GRUB pcie_aspm=force` check with nothing behind it | `verifySetup.sh` warned `not set (re-run 13-hardware.sh, then reboot)`, but `13-hardware.sh` had stopped doing that: 0.6.0 shipped a `5/6  Boot params` section that appended `pcie_aspm=force` to `/etc/default/grub`, it was later dropped (the step renumbered `5/6` → `5/5`, i.e. deliberately), and only the check was left orphaned. A boot-cmdline change nobody makes any more is not a battery finding — the check is removed, and the sibling TLP/power-profile checks stay. | `scripts/verifySetup.sh` |
| ufw reported inactive on a correctly-firewalled box | The audit ran `ufw status \| grep -i "Status: active"`, but `ufw status` refuses to run unprivileged — it prints `You need to be root to run this script` and exits 1. A normal-user `verifySetup.sh` therefore reported a permanently false "installed but not active" WARN whose advice (re-run `30-desktop-essentials.sh`) could never clear it. It now reads `ENABLED=yes/no` from the world-readable `/etc/ufw/ufw.conf`, escalating to `priv -n ufw status` only if that file is unreadable. | `scripts/verifySetup.sh` |
| Verify hints that name a step which cannot act on them | The three rows above are one class: a `verifySetup.sh` message saying `re-run <step>.sh` is a promise the step can clear the finding, and it was quietly broken twice — once by a check outliving its implementation, once by the finding sitting behind an unreachable branch. Guard **C20** makes it a build failure: every `re-run <step>.sh` hint must name a step script that exists, the DM loop may not `continue` past an installed rival, the purge offer must still be present, and no `if`/`elif ufw status` probe may run un-privileged. Each assertion was negative-tested by reintroducing the bug. | `tests/consistency.sh` (C20) |
| VSCodium repo key 404 | The old `download.vscodium.com/debs/pub.gpg` URL 404s, leaving a 0-byte keyring and a failing `apt update`. `40-vscodium.sh` now fetches from GitLab (with `repo.vscodium.dev` fallback), validates with `gpg --dearmor` + `gpg --batch --show-keys`, overwrites stale keyrings and refuses to add the repo unless the common trusted keyring exists. | `scripts/40-vscodium.sh`, `/usr/share/keyrings/vscodium-archive-keyring.gpg` |
| fastfetch config that fastfetch itself rejects | 0.8.x shipped a config with `general.showElapsed` and `general.statSeparatorType` — keys that have never existed in the schema. fastfetch printed `JsonConfig Error: Unknown general property`, rendered nothing, and **exited 221**, so every "run fastfetch" in the docs produced a one-line error and nothing caught it. The step now parses the config back with the installed binary and, on rejection, restores the previous config instead of leaving the broken one. Keys are pinned to the archived fastfetch (2.40.x), not the `dev` branch: `display.bar` is flat, `display.duration` and `{?var}` conditionals do not exist, and colours are the ANSI `38;2;R;G;B` form rather than hex. The guard is at run time rather than in the test suite on purpose — the schema belongs to whichever fastfetch is installed, so only that binary can be the authority. | `scripts/19-fastfetch.sh` |
| Prompt spent three forks per keystroke on `git` | 0.8.x called `git symbolic-ref`, fell back to `git rev-parse`, then `git status --porcelain` — on every prompt, two of them failing outside a repository. The branch is now read from `.git/HEAD` by bash itself (no fork; a `.git` *file* is followed, so worktrees and submodules work), and the dirty marker is a single `git status` with `GIT_OPTIONAL_LOCKS=0`. Measured, 50 prompts: **7.2 ms → 4.4 ms** inside a repo and **4.8 ms → 0.1 ms** outside one. A backgrounded cached status was rejected on purpose: bash prints `[1]+ Done ( trap … )` for every job it reaps, and the only fix is `disown`, whose `-a` form would also disown the user's own background jobs. | `configs/bash/prompt.sh` |
| Theme source of truth (engine-free) | The look is fixed: `Darkmatter` (+hdpi/xhdpi) and `Zafiro-icons-Dark` are **fetched at install time** from `stevedylandev/darkmatter-linux` / `zayronxio/Zafiro-icons` and tweaked by `scripts/lib/darkmatter-fetch.sh` (red-accent remap, hdpi/xhdpi variant assembly, `Zafiro-icons-Dark` naming + `apps/scalable` trim) — nothing is bundled in git. No palette engine, no per-user `~/.config/gtk-3.0/gtk.css`, no switcher — re-running `21-theme.sh` re-fetches/rebuilds from the cache. | `scripts/21-theme.sh`, `scripts/lib/darkmatter-fetch.sh`, `tests/` |
| Accent remap consistency | The upstream Darkmatter orange `#e78a53` is remapped to the red `#e75353` at install time across every text (css/scss/svg) + PNG asset. Tests exercise the remap against an offline fixture, assert the two bulky bundles are gone from the repo, and keep the old hex (`#e78a53`, Tokyo Night `#1a1b26`) out of shipped configs. | `scripts/lib/darkmatter-fetch.sh`, `tests/consistency.sh`, `tests/unit/test-darkmatter.sh` |
| picker.colors format | Key/value with `F2` alpha suffix on `bg0`/`bg3` (`bg0=#<hex>F2`); written statically by `21-theme.sh` and read by the Python menu/update GUI. | `scripts/21-theme.sh`, `configs/share/xfcemlg/*.py` |
| Update notifier without systemd | A cron job (09:00 + 18:00, marker comment) drives `xfce-update-check`; the .desktop action opens `xfce-update-gui` (VTE window running `apt-get full-upgrade`). No systemd timers. | `scripts/24-power-user.sh`, `configs/bin/xfce-update-*` |
| Update check without git remote | The repo has no remote, so `xfce-update-check` checks apt upgrades, not upstream releases. | `configs/bin/xfce-update-check` |
| XMLG_* env consistency | Escalator and install flags share one self-contained `XMLG_` namespace owned by this toolkit; `XMLG_PRIV` forces the escalator. | `scripts/lib/common.sh` |
| Test noise from derived trees | `live-sdk/` (permission-dense bootstrap), `blend/*/excalibur/rootfs-overlay/` and `__pycache__/` are pruned from lint `find` traversal and gitignored. | `tests/lint.sh`, `.gitignore` |
| Known-miss apt packages | `libdvd-pkg`, `winetricks` live in `contrib`, which the toolkit adds at install time but a bare source list lacks — allowlisted rather than failed. | `tests/lib/known-miss.list`, `scripts/lib/common.sh` `ensure_repo_component` |
| Long apt-checks wall time | One bulk `apt-cache dumpavail` (≈0.5 s for 69 k packages) plus `grep -Fx` replaces N × `apt-cache show` (~4 s/12 pkgs). | `tests/apt-checks.sh` |
| awk quoting in extractor | Package-label extraction lives in `tests/lib/extract-packages.sh`; apostrophes inside the awk block break bash single-quoting, so wording avoids contractions. | `tests/lib/extract-packages.sh` |
| Shell-capability of awk | The extractor uses POSIX `awk` (`match`/`RLENGTH`/`split`), which both gawk and mawk provide — no gawk-only extensions. | `tests/lib/extract-packages.sh` |
| Deb with grep-friendly lintian | `check-deb` runs `lintian -E` and drops the definitional `N:` notes; the standard library wants a changelog + python3 dep for the embedded widgets, both now shipped. | `Makefile`, `packages/xfcemlg-assets/` |
| Deb keeps git clone lean | Only DEBIAN metadata + `usr/share/doc/` are committed under `packages/`; the ~36 MB `configs/` payload (Darkmatter theme, Zafiro icons, wallpapers) is staged at build time (`make pkg-deb`), so one git checkout serves both the scripts and the package. | `Makefile` `pkg-deb` |
